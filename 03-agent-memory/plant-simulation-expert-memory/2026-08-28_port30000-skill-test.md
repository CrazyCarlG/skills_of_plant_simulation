## Key findings / decisions
1. **Bridge on port 30000 is fundamentally broken.** Every `simtalk_run` and `simtalk_syntax` payload returns `log="Unknown identifier 'hasSyntaxError'"`.
2. **Root cause**: The new SimtalkClaude bridge code calls `Method.hasSyntaxError(errMsg, errLine)`, which does NOT exist in old Plant Simulation. The bridge's own Method frame fails to compile, so user code never executes.
3. **ping works** (`{ "result": "success" }`) — handshake OK, failure is downstream.
4. **readlog returns stale content** (cached "copyFile" error from a prior unrelated operation), not new print output.
5. **`bfs_one_level.py` has a port-forwarding bug**: its main flow calls `simtalk_send.py` without `--port`, so it silently falls back to port 50007. The user thought it worked on 30000, but it actually hit 50007.
6. **Same payload succeeds on port 50007** (newer bridge, newer Plant Simulation) — confirmed the failure is the bridge, not the network or payload.
