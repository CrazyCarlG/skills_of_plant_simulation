# Plant Simulation CoPilot 插件原理总结

> 调研对象：`C:\ProgramFiles\Siemens\TecnomatixPlantSimulation2606\Copilot`
> 目标：在不打开 Plant Simulation 窗口的情况下，通过脚本调用 CoPilot 的会话能力。
> 关键结论：CoPilot 的"大脑"是一个本地 FastAPI 服务（端口 8002），完全独立于 Plant Simulation 窗口；任何能发 HTTP 的客户端（包括外部脚本）都可以调用。

**关键事实**：
- Python 进程由 Plant Simulation 启动，但**并不依赖** Plant Simulation 窗口。窗口只是 BrowserView（嵌入 Chromium）里的 UI。
- 服务监听 `http://localhost:8002`，可用任意 HTTP 客户端直接调用。
- C++ MCP 服务在 `http://localhost:8001/mcp`，**只有需要运行时工具**（语法检查、对象成员查询等）时才需要 Plant Simulation 进程在线。

## 3. HTTP API（FastAPI 端点）

由 `copilot_service.py` 暴露，全部绑定到 `COPILOT_SERVICE_PORT`（默认 **8002**）：

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| GET  | `/health` | 健康检查 | C++ 端用此判断 Python 是否就绪 |
| GET  | `/settings` | 查看当前 LLM 凭据（已脱敏） | |
| POST | `/settings` | 保存 LLM 凭据；保存前会用一次最小 LLM 调用做**验证** | 写 Windows Credential Manager |
| POST | `/validate` | 重新验证已保存凭据 | gcloud 重新登录后用 |
| POST | `/clear_memory` | 清空会话记忆（实际是换一个新 thread_id） | |
| POST | `/feedback` | Langfuse 反馈（仅 COPILOT_DEBUG=1 时可用） | |
| POST | `/shutdown` | 优雅关闭本服务 | C++ 用来杀掉孤儿进程 |
| POST | `/query` | 阻塞式问答，返回 JSON `{answer, citations, trace_id, metrics}` | |
| POST | `/query/stream` | **SSE 流式**，逐 token 输出 | BrowserView 实际用的就是它 |

**最关键的两个**：`/query` 与 `/query/stream`。
- 请求体：`{"question": "..."}`
- `/query/stream` 的事件流：
  - `event: token` —— 每段 LLM 文本片段
  - `event: done`  —— 一次性 JSON：包含最终 answer、citations、metrics（耗时 / token / 工具调用）

## 4. LangGraph Agent 与工具集

Agent 由 `langchain.agents.create_agent` 创建，配 `MemorySaver` 检查点：

- **记忆机制**：每个 `thread_id` 一份独立会话历史。`/clear_memory` 的实现只是把全局 `_thread_id` 换成一个新 uuid。
- **系统提示**（`SYSTEM_PROMPT`）写死在 `copilot_service.py:204-310`，包含两条**绝对规则**：
  1. 任何 SimTalk 代码块必须先用 `check_simtalk_syntax` 校验。
  2. 不能仅凭 `get_object_methods_and_attributes` 的结果描述成员——必须先经 `search_chunks_keyword` + `get_complete_documents` 拿到真实文档。
- **工具集**：
  | 类别 | 工具 | 来源 |
  |---|---|---|
  | 检索 | `search_chunks_semantic` | 本地函数（直接调 vicinity） |
  | 检索 | `search_chunks_keyword` | 本地函数（BM25s） |
  | 检索 | `get_complete_documents` | 本地函数（SQLite 拼装） |
  | 重构 | `refactor_with_anonymous_identifiers` | 本地函数（返回 `@`/`?` 文档） |
  | 运行时 | `check_simtalk_syntax` | **MCP**（C++ 端 8001） |
  | 运行时 | `verify_method_or_attribute` | **MCP**（C++ 端 8001） |
  | 运行时 | `get_object_methods_and_attributes` | **MCP**（C++ 端 8001） |

注意：**RAG 工具是 in-process 调用的，不走 MCP**（`copilot_service.py:1147-1184`）。只有需要 Plant Simulation 运行时能力的工具才通过 `langchain_mcp_adapters.MultiServerMCPClient` 连到 8001。

## 5. LLM Provider 适配

支持五种 provider，由 Windows Credential Manager 中存的一条 JSON 决定（`target = "PlantSimulation/CoPilot"`）：

- `aws`（Bedrock，支持 bearer token 或 IAM key）
- `azure`（Azure OpenAI）
- `anthropic`（Anthropic 直连，可自定义 `base_url`）
- `google_vertex`（Gemini via Vertex AI，使用 ADC）
- `openai_compatible`（Ollama / Groq / Mistral / 私有云等）

凭据用 ctypes 直接调 `advapi32` 的 `CredReadW/CredWriteW`，**不依赖** `keyring` 包，target 名干净。`/settings` 接口会先**真正调一次 LLM**（`max_tokens=5`）确认凭据有效，才落盘。

## 6. 启动流程

1. 一次性 `setup.bat`（用户双击）：
   - 写入 `python314._pth` 启用 `import site` + `Lib/site-packages`
   - 装 pip（如果没有）
   - `pip install -r requirements.txt` 进嵌入式 Python
2. Plant Simulation 启动 → 启动 BrowserView → **拉起子进程**：
   ```
   python-3.14.5-embed\python.exe copilot_service.py
   ```
   （由 C++ 进程管理，端口 8002）
3. 子进程 `lifespan`：
   - 异步 `initialize()`：连接 MCP（10s 超时）、加载 RAG 索引、构造 LLM、`create_agent`
   - C++ 轮询 `/health`，看到 `agent_ready: true` 就把 loading 蒙层去掉
4. 用户在 BrowserView 提问 → `/query/stream` → LangGraph agent → 工具调用循环 → SSE 回流

## 7. 不开窗口如何调用？（你的目标）

> **结论**：Python FastAPI 服务本身就是公开的 HTTP 服务，**根本不需要 Plant Simulation 窗口**。窗口只是 BrowserView（一个 HTTP 客户端）。你完全可以写一个外部脚本，按相同协议 POST 到 `http://localhost:8002/query`（或 `/query/stream`）即可。

### 7.1 前置条件

要复用本机的 CoPilot 服务，最少需要两件事：

1. **嵌入式 Python + 依赖已就绪**（运行过 `setup.bat`）。
2. **LLM 凭据已配置**（在 BrowserView 设置面板里配过；或直接通过 `POST /settings` 写入）。
3. **服务进程在运行**。两种拉起方式：
   - **方式 A（推荐）**：用 `python-3.14.5-embed\python.exe` 直接跑 `copilot_service.py`，不走 Plant Simulation 进程。
     ```bash
     python-3.14.5-embed\python.exe copilot_service.py
     ```
   - **方式 B**：先启动 Plant Simulation 加载一个 .spp，让它自己起子进程。

### 7.2 与"运行时工具"的关系

- 如果你的问题**只涉及 RAG 知识**（SimTalk 语法解释、API 文档、示例代码片段），**完全不需要** Plant Simulation 运行。
- 如果 Agent 在推理过程中**主动调用** `check_simtalk_syntax` / `verify_method_or_attribute` / `get_object_methods_and_attributes`，则需要 8001 端口上有 MCP 服务（即 Plant Simulation 在跑）。
- 通过 `POST /health` 的 `local_tools` / `mcp_tools` 字段可以判断 RAG 工具和运行时工具是否都可用。

### 7.3 最简调用示例（外部脚本）

```python
import requests

BASE = "http://localhost:8002"

# 1) 健康检查
print(requests.get(f"{BASE}/health").json())
# -> {'status': 'ok', 'agent_ready': True, 'has_credentials': True,
#     'local_tools': 4, 'mcp_tools': 3}

# 2) 阻塞式问答
r = requests.post(f"{BASE}/query", json={"question": "如何用 SimTalk 创建一个 Buffer？"})
print(r.json()["answer"])

# 3) SSE 流式
import json
with requests.post(f"{BASE}/query/stream",
                  json={"question": "解释一下 MUs 的 .cont 属性"},
                  stream=True) as r:
    for line in r.iter_lines():
        if not line: continue
        if line.startswith(b"event: token"):
            continue
        if line.startswith(b"data:"):
            payload = line[5:].strip()
            try:
                obj = json.loads(payload)
                if isinstance(obj, dict) and "answer" in obj:
                    print("\n--- final answer ---")
                    print(obj["answer"])
                    print("citations:", obj["citations"])
            except json.JSONDecodeError:
                print(payload.decode("utf-8", "ignore"), end="", flush=True)

# 4) 多轮对话：保留 thread_id（目前 API 没有把它暴露成请求参数，
#    所以严格意义上“外部脚本多轮”需要改 copilot_service.py 把 thread_id
#    改成从 query 体里读取；或用 /clear_memory 显式重置）。
```

### 7.4 如果想支持多轮 / 会话隔离

当前实现是**单全局 thread_id**（`copilot_service.py:344`），每次启动或 `/clear_memory` 时换新 uuid。要让外部脚本维持自己的会话，需要做最小改动：

- 在 `QueryRequest` 中加 `thread_id: Optional[str] = None`
- 在 `query_stream` / `query` 中用 `req.thread_id or _thread_id`
- 服务可同时支持多个外部客户端，每个客户端用各自的 thread_id

这是把它变成"通用 SimTalk 知识问答 API"的关键补丁（参见 09-改造建议.md）。

## 10. 一句话总结

> CoPilot 的"会话能力"完全封装在 `http://localhost:8002` 这个 FastAPI 服务里，Plant Simulation 窗口只是其中一个客户端。你只需让服务跑起来（用嵌入式 Python 拉起即可），就能用任意 HTTP 客户端调用 `/query` 或 `/query/stream`，得到与 BrowserView 完全相同的 SimTalk 知识问答。
