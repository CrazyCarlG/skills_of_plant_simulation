# Code templates for `local-simtalk-modify-object-attribute`

> Copy-paste SimTalk snippets for every supported attribute type. Each
> template uses the standard `read → write → read → print markers` pattern
> so values can be recovered via `print + readlog` (Quirk #6 means the socket
> itself never carries the value).

## Naming convention

All templates use:
- `<PATH>` — the Plant Simulation path, e.g. `.Models.Model.EventController`
- `<ATTR>` — the attribute name on that object
- `<NEW_VALUE>` — the value you want to assign

The script `scripts/attr_modify.py` fills these in for you automatically. Use
this reference when you need to send raw `simtalk_run` payloads (e.g., for
non-attribute modifications or method calls).

---

## boolean

```simtalk
var obj: object := str_to_obj("<PATH>")
if obj = void
  print "###MARKER###"
  print "ERR: void path"
  print "###END###"
  return
end
var before: boolean := obj.<ATTR>
obj.<ATTR> := <NEW_VALUE>     -- true | false
var after: boolean := obj.<ATTR>
print "###MARKER###"
print "<ATTR>: " + to_str(before) + " -> " + to_str(after)
print "###END###"
```

Example: `obj.<ATTR> := false`

## string

```simtalk
var obj: object := str_to_obj("<PATH>")
var before: string := obj.<ATTR>
obj.<ATTR> := "<NEW_VALUE>"   -- escape \" and \\ inside
var after: string := obj.<ATTR>
print "###MARKER###"
print "<ATTR>: " + before + " -> " + after
print "###END###"
```

For long strings, build with `+` concatenation; the literal limit is around
2 KB per `print` statement in Plant Simulation.

## dateTime

```simtalk
var obj: object := str_to_obj("<PATH>")
var before: dateTime := obj.<ATTR>
obj.<ATTR> := str_to_dateTime("<NEW_VALUE>")   -- e.g. "2026/01/02 14:00:00"
var after: dateTime := obj.<ATTR>
print "###MARKER###"
print "<ATTR>: " + to_str(before) + " -> " + to_str(after)
print "###END###"
```

Date format: `YYYY/MM/DD HH:MM:SS`. Other formats may need `str_to_dateTime`
with explicit format string.

## object / method

```simtalk
var obj: object := str_to_obj("<PATH>")
var before: object := obj.<ATTR>
obj.<ATTR> := str_to_obj("<NEW_VALUE>")     -- for object-typed attrs
-- OR for method-typed attrs:
-- obj.<ATTR> := &myMethod                   -- note the & sigil
var after: object := obj.<ATTR>
print "###MARKER###"
print "<ATTR>: " + obj_to_str(before) + " -> " + obj_to_str(after)
print "###END###"
```

For method-typed attributes (`InitCtrl`, `ResetCtrl`, `StartStopCtrl`),
the assignment uses `&methodName` syntax. **Not supported by
`attr_modify.py` automatically** — write the SimTalk by hand.

## Multiple attributes on the same object (manual)

If you need to read or write multiple attributes atomically (in a single
`simtalk_run` transaction):

```simtalk
var obj: object := str_to_obj("<PATH>")
var b1: boolean := obj.<ATTR1>
var b2: real := obj.<ATTR2>
var b3: integer := obj.<ATTR3>
obj.<ATTR1> := <NEW1>
obj.<ATTR2> := <NEW2>
obj.<ATTR3> := <NEW3>
var a1: boolean := obj.<ATTR1>
var a2: real := obj.<ATTR2>
var a3: integer := obj.<ATTR3>
print "###MARKER###"
print "<ATTR1>: " + to_str(b1) + " -> " + to_str(a1)
print "<ATTR2>: " + to_str(b2) + " -> " + to_str(a2)
print "<ATTR3>: " + to_str(b3) + " -> " + to_str(a3)
print "###END###"
```

This is a single TCP round-trip and is safer for transactional consistency,
but you lose the per-attribute `simtalk_run` failure isolation that
`attr_modify.py --batch` provides.

## Restore template (auto-generated by `--restore`)

```simtalk
var obj: object := str_to_obj("<PATH>")
obj.<ATTR> := <ORIGINAL_VALUE_AS_LITERAL>
print "restored: <PATH>.<ATTR> := " + to_str(obj.<ATTR>)
```

`scripts/attr_modify.py` builds this automatically from the captured
`before` values when `--restore` is passed. Each restored attribute is a
fresh `str_to_obj` call so a stale local reference can't accidentally
write to the wrong object.

## Marker parsing reference

The `###MARKER###` / `###END###` pattern is used by the helper script and by
the bfs_one_level script in `local-simtalk-get-folder-tree`. The format is:

```
###MARKER###
<free-form content — usually one line per attribute>
###END###
```

Anything between the markers is parsed by re.search with a non-greedy regex.
Trailing newlines after `###END###` are ignored.
