## Two bugs fixed (lessons learned)

### Bug 1 — argparse `nargs="+"` 与 `add_note.py --note` 的 REPLACE 陷阱

`add_note.py` 把 `--note` 定义为 `nargs="+"` 但**没有** `action="append"`。
结果：传入重复的 `--note A --note B --note C --note D` 时，argparse 每次
**覆盖** `args.note`，最终 `args.note == ['D']` —— 前 3 行被静默丢弃。

```text
[broken]   --note A --note B --note C --note D  → args.note = ['D']
[fixed]    --note A B C D                        → args.note = ['A','B','C','D']
```

**修法（write_simtalk.py 已经改完）**：把**所有**代码行作为**单个**
`--note` 的位置参数传入：

```python
cmd = [sys.executable, ADD_NOTE_SCRIPT,
       "--path", method_path, "--mode", "replace", "--confirm", "--note"]
cmd.extend(code_lines)   # 单个 --note，多个值
```

### Bug 2 — `method`（小写）是 SimTalk 保留字

Plant Simulation 的 SimTalk lexer 把 `method` 当作 data type 关键字，
新建 `.Models.Model.method` 时直接报 "Invalid identifier or identifier
already exists in the name scope"。

**绕过**：Frame 自动生成的默认 Method 名字是 `Method`（大写 M），直接
复用即可。如果需要不同名字，挑一个非保留字的标识符。

## Step 5 — 创建 Method 实例（三种失败的 `create()` 写法）

`create` 同时是 SimTalk 关键字 + List 方法，**不能**用来实例化
InformationFlow 对象（Method / Variable / etc.）。三种"看起来合理"的
写法都失败：

```simtalk
-- ❌ 写法 1：object reference 上调 create
var p: object := str_to_obj(".InformationFlow.Method");
p.create(f, "x");                     -- Unknown identifier 'create'

-- ❌ 写法 2：data-type 路径调 create
.InformationFlow.Method.create(f, "x");  -- 'create' can only be applied to lists

-- ❌ 写法 3：data-type 路径 + & 调 create
.InformationFlow.&Method.create(f, "x"); -- 'create' 仍是保留字，仍然失败

-- ✅ 唯一可行：用 duplicate() + & 引用操作符
var f: object := str_to_obj(".Models.Model");
.InformationFlow.&Method.duplicate(f, "myMethod");
```

关键细节：
1. `&` 加在路径**最后一段**前（`.InformationFlow.&Method`），
   告诉 SimTalk 把名字当 class object 而不是 data type `Method`。
2. `<frame>` 参数是 **object 引用**，不是 string。必须先
   `var f: object := str_to_obj(...)` 再传 `f`（不带引号）。
4. 文档出处：`01-plantsimulation-knowledge/01-plant-simulation-help/objects/common-methods/common-methods.md` line 164。

## 新发现 — 用 `local-simtalk-class-management` 创建 Method 实例

> 来自用户提示 + 本会话实测验证：用户提示"`创建method对象可以使用
> local-simtalk-class-management 技能`"。此前 write_simtalk.py 的文档
> 误以为 class_ops.py `duplicate` 只动 Class Library，实测发现它
> **也能创建 Frame 实例**（只要 `dest` 指向 Frame 而非 Folder）。

### 实测验证

```bash
# 创建：把 .InformationFlow.Method 的实例塞进 .Models.Model
python3 ../local-simtalk-class-management/scripts/class_ops.py \
    duplicate .InformationFlow.Method .Models.Model test_method_from_cm
```

返回 envelope：

```json
{
  "ok": true,
  "subcommand": "duplicate",
  "data": {
    "BEFORE_PATH": ".InformationFlow.Method",
    "BEFORE_NAME": "Method",
    "BEFORE_TYPE": "Method",
    "AFTER_PATH": ".Models.Model.test_method_from_cm",
    "AFTER_NAME": "test_method_from_cm",
    "AFTER_TYPE": "Method",
    "AFTER_ORIGIN": ".InformationFlow.Method",
    "AFTER_ORIGINROOT": ".InformationFlow.Method",
    "AFTER_CLASS": ".InformationFlow.Method"
  }
}
```

`inspect` 二次确认：`TYPE=Method, ORIGIN=.InformationFlow.Method,
NUMATTRIBUTES=0, NUMCHILDREN=0`。
`delete` 清理成功。

### 为什么这能 work

Plant Simulation 的 `duplicate()` 方法的 `Destination:object` 参数
**同时接受 Folder 和 Frame**：

- 传入 Folder → 在 Class Library 里创建新 class（class_ops.py 的
  文档化的主用法）。
- 传入 Frame  → 在该 Frame 里创建新 instance（write_simtalk.py 的
  Step 5 用的就是这条路）。

`class_ops.py duplicate` 的 SimTalk 生成模板：

```simtalk
var srcObj: object := str_to_obj("<path>")
srcObj.duplicate(str_to_obj("<dest>"), "<name>")
```

注意：`srcObj` 是 `str_to_obj(...)` 拿到的 object 引用，所以**不需要**
`&` 操作符 —— `&` 是 dot-path 字面量语法里用来规避 data type 冲突的，
object reference 调用没有这个问题。

文档原文（`common-methods.md` line 166）：
```simtalk
var myConveyor: object := .MaterialFlow.Conveyor.duplicate(.Models.Model, "MyConveyor")
```

### write_simtalk.py 与 class_ops.py 的两条路

| 路径 | 何时用 | 何时**不**用 |
|---|---|---|
| `write_simtalk.py --frame .Models.Model --new-method myMethod` | 一次性创建 + 立即写入源代码（一步到位） | 想做 dry-run 看会发什么；想做 raw SimTalk |
| `class_ops.py duplicate .InformationFlow.Method .Models.Model myMethod` | 单纯创建实例（不写代码）→ 后续 `add_note.py --mode replace --path ...` 写源代码 | 想自动校验 `&` 之类的 dot-path 细节（class_ops.py 走 `str_to_obj` 自动绕过） |

实际上两条路最终都调用 `.duplicate()`。差别是：
- write_simtalk.py 用 dot-path 字面量（需要 `&`），并自行负责
  parent / frame 路径的 typecheck。
- class_ops.py 用 `str_to_obj` 拿到 object 引用（不需要 `&`），并
  提供完整的 JSON envelope（before / after / log_tail）方便脚本
  化处理。

### 写代码部分仍推荐 write_simtalk.py / add_note.py

`class_ops.py` 只负责创建实例（duplicate）和清理（delete）。它**不能**
直接写源代码。要写代码，仍然走：

```bash
python3 ../local-simtalk-add-note-to-method/scripts/add_note.py \
    --path .Models.Model.myMethod \
    --mode replace --confirm \
    --note "line1" "line2" "line3" ...
```

或者一步到位的 `write_simtalk.py`。

## 之前已经修过的 argparse 行为细节

`write_simtalk.py write_code()` 仍然保留 Quirk #10 的告警：如果 source
code 里某行以 `--` 开头（例如 `-- comment`），subprocess argv list
模式下不会丢行（因为 shell 没参与 tokenize），但如果改用 `shell=True`
就会触发 argparse 在第一个 `--xxx` 处停止消费 `--note` 的位置参数。
当前实现保持 list 模式 + 防御性 warn（不 abort）。

## 后续事项 / 不要重做的事

1. **不要**用 `var p: object := str_to_obj(...); p.create(...)` 创建
   Method 实例 —— 100% 失败。
2. **不要**给 `add_note.py` 传重复的 `--note A --note B ...` —— argparse
   会丢行。改用 `--note A B C ...`。
3. **不要**给小写 `method` / `variable` / `table` / `list` 等作 Method
   名 —— 撞保留字。换非保留字或复用 Frame 自带的 `Method`（大写 M）。
4. **不要**把 `class_ops.py duplicate` 想成"只动 Class Library"——
   Frame 实例它也能建（用户提示 + 实测确认）。
