# Knowledge Base Layout

The local Plant Simulation knowledge base lives at
`01-plantsimulation-knowledge/01-plant-simulation-help/`. Every search in
`find_related.py` walks this tree.

## Section tree

| Section (`--kind`) | Path prefix | Content |
|---|---|---|
| `getting-to-know` | `getting-to-know-plant-simulation/` | Intro concepts, folder model |
| `objects` | `objects/<kind>-objects/<ObjectName>/` | One folder per object (`Buffer`, `Station`, `Worker`, ...) with sub-folders `attributes/`, `methods/`, `general/`, plus shared `common-attributes/` etc. |
| `simtalk` | `simtalk/<topic-slug>/` | Language fundamentals, data types, control flow, predefined functions (I / II / III), 3D APIs, migration notes, deprecated names, toolbox/folder-library access |
| `step-by-step` | `step-by-step/<scenario>/` | Hands-on scenarios (material flow, robots, animation, fluids, transport, ...) |
| `communication-interface` | `communication-interface/<COM\|Socket>` | COM / Socket interface reference |

> `--kind any` (the default) walks the entire tree.

## File naming

| Suffix | Meaning | Notes |
|---|---|---|
| `.md` | Curated, hand-structured documentation | Preferred for `Read`-ing into context |
| `.txtx` | Raw text extracted from the source PDF | Often a near-duplicate of the matching `.md`; useful when the curated doc is missing a topic |
| `README.md` | Per-section index / summary | Auto-generated by the PDF→knowledge pipeline; surfaced as `[INDEX]` and de-weighted by `-3` unless `--include-index` is passed |

> When `.md` and `.txtx` both rank for a query, the `.md` is the authoritative version — prefer it. The script does not auto-deduplicate because either may be the only source available.

## Common sub-folders under `objects/<kind>-objects/<ObjectName>/`

- `attributes/` — attribute reference (read / write / read-only)
- `methods/` — method reference (signatures + behavior)
- `general/` — overview, usage patterns, related objects
- (less common) `events/`, `states/`, `dressing-rules/`, ...

## Common sub-folders under `simtalk/<topic-slug>/`

- Often a single canonical doc per topic (e.g. `language-fundamentals/values-variables-parameters/values-variables-parameters.md`)
- Some topics (e.g. `predefined-functions-iii-...`) fan out into per-function sub-folders (`for-any/`, `model-debugging/`, ...)

## Search-side hints

- **Object lookup** (e.g. `Buffer`, `WorkerPool`, `PickAndPlace Robot`) → use `--kind objects`, top result usually points to `<ObjectName>/attributes/attributes.md` and `<ObjectName>/general/general.md`.
- **SimTalk syntax / function lookup** → use `--kind simtalk`. `predefined-functions-i-...` (OS / math / string / datetime), `predefined-functions-ii-...` (HTTP / utilities), `predefined-functions-iii-...` (type queries / I/O / debug) are the three function catalogs.
- **"How do I ...?" modeling question** → use `--kind step-by-step`.
- **COM / Socket programming** → use `--kind communication-interface`.
- If unsure, drop `--kind` and read the top-3 with breadcrumbs to decide.

## When a query is too narrow

- Drop `--kind`, broaden keywords, or pass `--include-index` to surface README summaries that aggregate multiple topics.
- Exit code `3` means *no matches* — broaden the query or check spelling.
