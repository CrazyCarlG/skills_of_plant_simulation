# Lifelines — Hard Rules

> Every "must / must not / will go wrong" rule for this skill lives here.
> Other docs reference this file; do not duplicate rules elsewhere.

## 1. Read-only

- The skill **never writes** to anything inside `01-plantsimulation-knowledge/`.
- It does not create / append / move files anywhere in the repo (no `log/` dir).
- If a downstream task needs to *edit* a doc, route through whatever pipeline
  owns that doc (e.g. `01-plantsimulation-knowledge/scripts/pdf-to-knowledge/`) —
  not through this skill.

## 2. Knowledge-base root resolution

`find_related.py` resolves the root in this order:

1. `--root <absolute-path>` if given
2. `<repo-root>/01-plantsimulation-knowledge/01-plant-simulation-help` (sibling of `skills/`)
3. `<cwd>/01-plantsimulation-knowledge/01-plant-simulation-help`

If none of these exist → exit code `2`, with a hint to pass `--root`.

## 3. Search contract

| What you must do | Why |
|---|---|
| Pass `--query` (free text). Empty / sub-2-char tokens are dropped, so a 1-char `--query a` returns exit `1`. | Avoids floods of useless matches. |
| Use `--kind` to scope to one section (`objects`, `simtalk`, `step-by-step`, `communication-interface`, `getting-to-know`, `any`). | Prevents cross-section pollution (e.g. "Worker" matches material-flow docs and resource docs). |
| Use `--top N` (default 10). | The knowledge base is ~600 files; top-N caps context cost. |
| Read the printed `rel_path` with your own `Read` tool — the script returns *paths + snippets*, not full content. | Keeps the script stateless and lets Claude decide how much of each file to load. |
| Trust the `snippet` to decide whether a hit is relevant — it shows the first matching line(s) with the first token wrapped in `<<…>>`. | Snippet is the cheapest signal that the file actually contains the topic. |

## 4. Scoring

Each file gets `score = 5·filename_hits + 3·path_hits + body_hits` (body capped at `MAX_BODY_HITS = 20`).

- Filename hits weigh most (object names often match exactly: `Buffer.md`, `WorkerPool.md`).
- Path hits weigh next (e.g. query "Worker" + path `resource-objects/`).
- Body hits provide volume but are capped so a single huge doc cannot dominate.

`README.md` index files get `-3` penalty unless `--include-index` is passed — they are summaries, not primary sources.

`MAX_BODY_BYTES = 1_500_000` (~1.5 MB) — files larger than this skip the body scan and fall back to filename + path scoring only (with half-credit for "having content").

## 5. Exit codes

| Code | Meaning | Caller action |
|---|---|---|
| `0` | success, at least one match | read the printed `rel_path`s |
| `1` | bad arguments (e.g. `--top 0`, no usable tokens in `--query`) | fix args and retry |
| `2` | knowledge base root not found | pass `--root <absolute-path>` |
| `3` | no matches | drop `--kind`, broaden `--query`, or pass `--include-index` |

> argparse itself uses exit `2` for missing required flags. That's expected.

## 6. Windows encoding trap

Default Windows console code page is `cp1252`, which crashes on characters like
`→` or Chinese punctuation that appear throughout the SimTalk docs. The script
calls `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` at startup
(Python 3.7+); do not bypass it. If you pipe the script into another tool that
forces cp1252, redirect through `PYTHONIOENCODING=utf-8`.

## 7. Do not modify the knowledge base

If a search surfaces outdated / incorrect content, do **not** patch the `.md`
in place — that knowledge base is regenerated by the PDF→knowledge pipeline.
Surface the issue upstream and let the pipeline owner fix it.
