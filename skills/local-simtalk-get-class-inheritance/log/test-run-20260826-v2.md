### 4.3 关键发现 / Critical Insight

**`.SimtalkClaude` 是一个用户自定义的 dispatch framework**，结构为：

```
.SimtalkClaude                                  (Folder)
├── .Objects                                    (Folder — class library)
│   ├── Button, DataTable, DataList, Dialog, HtmlReport, Method, Socket, Variable
│   └── (上述为 8 个用户定义的"类")
├── .connection                                 (Folder)
│   ├── Logger, SocketClient, SocketServer      (Frame — 框架运行时对象)
│   └── (其成员是从 .Objects.* 派生的实例)
├── .main                                       (Frame — 主入口)
│   ├── Server (Variable) ← .Objects.Variable
│   ├── SimtalkAction (Frame) ← .src.SimtalkAction
│   └── SocketClient/SocketServer (Frames) ← .connection.*
└── .src                                        (Folder — 原始定义副本)
    ├── SimtalkAction, ErrorHandler, autoexec
    └── (与 .main.* 同对象 — 提供 Origin 链首端)
```

📌 **本测试直接回答用户的疑问**：`SimtalkClaude` 不是普通文件夹，它有 **自成一体的类继承体系** — `.Objects.*` 是用户自定义的"类库"，`.connection.*` 和 `.main.*` 是其实例化与派生态。这正是 v1 测试被漏掉的部分。

## 9. 结论 / Conclusions

1. **用户反馈的"不全"已被补齐 ✅** — `.SimtalkClaude.*` 子树共 60 个 unique paths 全部 capture（94 个 input，34 个 duplicate / src-* 同名对象已通过 main-* 路径覆盖）。
2. **`.SimtalkClaude` 是用户自定义 dispatch framework** — 它有自成一体的类继承体系（`.Objects.*` 是类库，`.connection.*` 和 `.main.*` 是派生态）。
3. **18 个 root classes** 全部是 Plant Simulation 内置 *或* 用户 dispatch framework 顶层的类库对象。
4. **42 个 derived classes** 全部派生自 `.Objects.Button/DataTable/Method/Socket/Variable` 或 `.connection.*` Frame。
5. **3 个 dead paths** (`.SimtalkClaude.main.SimtalkAction.a_read*`) 提示 folder-tree 缓存中存在陈旧条目 — 未来可加入 dead-path 过滤逻辑。
6. **readlog v15+ 截断（INH-1）再次触发** — batch 5/7/8 各返 0 行；建议未来小批量收紧到 8 paths/batch，或加 `sleep 2` 在 batch 间。
7. **skill 的 candidate-generation 需要扩展** — 当前的 `paths.txt` 过滤器会排除所有 Folder/Frame/Method/Variable，**完全错过** `.SimtalkClaude.Objects.*`（8 个用户定义的"类"）。如要让 skill 自动发现整个模型的继承图，需把 filter 改为只排除明显的非类（`Folder`/`Method`/`Variable`/`DataTable`/`Socket`/`Button`/`Dialog`/`Chart`/`HtmlReport`/`DataList`/`Comment`/`FileLink`），但保留 `Frame`（用户 Frame 也可能有 class 继承）— 见 `references/exploration-log.md` 中的"future work"。

## 10. 后续建议 / Recommendations

1. **更新 `SKILL.md` 的 candidate-generation 章节** — 明确指出 `.Objects.*` 这种"用户类库 folder"也是 class root class 来源。
2. **将 batch size 进一步收紧** — 94 paths 触发了 3 个 batch 失败。考虑降到 8 paths/batch 或加入 inter-batch sleep。
3. **加入 dead-path 过滤** — `OriginRoot == "VOID"` 且 `name == ""` 的行（str_to_obj 返 void）应被标记为 missing 而非归入 root classes。
4. **补一个 `scripts/probe_inheritance.py --dedupe-by-name` 选项** — 当同对象被多条路径访问时只记录第一条，避免 60 → 60 但覆盖更完整。
5. **本测试日志与 v1 共存** — `log/test-run-20260826-v1.md`（12 paths 内置类）+ `log/test-run-20260826-v2.md`（60 paths dispatch framework）共同构成 skill 的完整 end-to-end 验证记录。
